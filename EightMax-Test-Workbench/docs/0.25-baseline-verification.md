## Reproduced defects and gaps (all confirmed in the 0.24.0 sources / reports)
1. **CPU and memory double counting — reproduced.** `docs/0.24-benchmark-pipeline-linux-simulated.json` (2 tables, 2 workers): `cpuMs 14,255.6` over `wallMs 3,563.8` = `cpuCoresBusy 4.0000876` although each worker runs one cooperative loop; `peakRssBytesSum` 796,704,768 B (a sum of per-worker whole-process RSS). Cause: `tools/pipeline-worker.cjs` read `process.cpuUsage()` / `process.memoryUsage().rss` inside worker threads (process-wide) and `tools/multitable-benchmark-024.cjs` summed them.
2. **Flaky test in the baseline.** `tests/multitable.test.cjs` "memory budget: pressure holds tables…" failed in 4 of 6 isolated runs of the **unmodified 0.24.0** (it passed in the full-suite run): the memory governor first ran on a 20 ms timer, which a fast 6-table run can finish before.
3. **Fallback dependence — reproduced** (`docs/0.24-full-hand-scenario.json`, seed 2024): 255 solver / 33 scripted (88.5 %). Causes: 25 × "no stored strategy for this hand at node" (sampled training never visited the information set), 7 × off-tree wager from a scripted raise ("not a tree size"), 1 × street not covered.
4. **Windows Graphics Capture not implemented**; Win32 PrintWindow/BitBlt/DWM code never run on Windows.
5. **Image recognition validated only on the controlled renderer** (synthetic + Chromium rendering of the same client); no real-client measurement.
6. **No GPU code path**; no target-hardware (i7-13th gen / RTX 4060 Ti) measurement.
7. **Platform coupling**: the vision layout was a fixed in-code constant (`defaultLayoutV2`); a new table layout needed source edits; no profile system.
