The 3 failures are pre-existing and environmental, not functional: the 0.33 report's own Linux run had no Mono, so these tests were
skipped there; this container could install Mono, so they ran:
1. *"the shipped host equals a fresh Mono build of its source"* — stale since 0.33: the shipped host is built on Windows with the
   .NET Framework compiler, so a Mono build cannot have the same size (0.35 rewrites this assertion; see the validation report).
2. and 3. *host shutdown / 503 host-stopping* — needed the `openbox` window manager, which was then installed.

The 57 skips need a Linux build of the native EightMax CLI (`EIGHTMAX_TEST_CLI`), Playwright features or PowerShell 7; on Windows the
same suite runs with the shipped `mwcli.exe` (see the Windows CI runs in the validation report).

Inspected and preserved: `src/execution-adapters.js` (UiAutomationAdapter: `activate`, `enterAmount`, mock-tested only in 0.33),
`src/test-executor.js`, `src/platform-profile.js`, `src/capture-manager.js`, `src/screen-capture.js`, `src/desktop-host.js`,
`desktop/DesktopHost.cs`, `desktop/CaptureService.cs`, `tests/execution-adapters.test.cjs`. One defect was visible already on
inspection: the UI adapter recorded the idempotency key only after the click resolved while the executor retried on an
acknowledgement timeout — a slow click could have been sent twice (fixed in 0.35, test in `tests/simulator-controls-035.test.cjs`).
