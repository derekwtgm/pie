NEW IN 0.18.0 — KNOW WHEN A STUDY HAS TRAINED ENOUGH
1. Native CPU job controls now include a Convergence check (Auto by default), how
   often to check, a per-check time limit and a target as % of the starting pot.
2. After training, the engine's own best-response check reports how much each seat
   could still gain by changing its strategy. Auto uses the exact check, then falls
   back to restricted or sampled checks on trees that are too big.
3. Imported results show a verdict:
   Within target — exact check at or below your target.
   Keep training — gain is above target; resume with more updates.
   Not proven — only a lower-bound check ran; it cannot confirm convergence.
   Unavailable — no check could finish; the training result is still usable.
4. Set "Check every N checkpoints" above 0 to see a curve of the largest gain.
5. Limits raised: up to 10,000,000 native updates, 16,384 MiB strategy memory
   (refused if your PC lacks the RAM), 7-day training time limit, checkpoints up to
   every 1,000,000 updates. Browser studies may now run up to 10 minutes.
6. Older jobs, results and workspaces still open. Browser-only studies are not
   convergence-checked; export them as native jobs to measure.
See docs/CONVERGENCE.md for how to read the numbers and the exact scope.

Existing manifests open with Open labeled manifest. Select their original images;

Accepted accuracy is correct accepted labels / all accepted labels, including
false accepts on Must reject fields. Known-field coverage includes EVERY known
expected field, so a missing file/region lowers coverage. Missing evidence is
unscored, never a successful rejection. False-accept rate uses only scored negative
examples. A denominator with no evidence is shown as Unavailable, not perfect.

Reports include per-table/per-field metrics and wrong-label confusion counts.
They flag normalized crops exactly equal to reference samples and also show
metrics without that exact overlap. This does NOT prove holdout independence:
near-duplicate images, related sessions and mislabeled ground truth can still
mislead. Amount labels use exact spelling: 100 and 100.00 are distinct labels.
Similarity scores remain heuristic matches, not calibrated probabilities.

Only one dataset image is decoded at a time during validation. Each is bounded to
10 MB / 20 MP; selected files total 100 MB / 100 images. Manifests allow 200 cases,
2,000 expected fields and 4 MB UTF-8. These are input bounds, not a measured RAM
cap. Bitmap size is checked after decode. A pending decoder may finish after Stop,
but its cancelled result is discarded. No partial report can be exported.

Validation pauses the simulator and cancels portable studies, and blocks new
simulator/study/capacity runs until it finishes/stops. Global Emergency stop/Escape
also cancels validation. Separate native jobs are outside browser controls.
Validation reports omit screenshot and template pixels. Datasets, selected files
and validation drafts/results are not part of observation/simulation recovery.

A review file keeps the original observation sequence, cursor, evidence settings
and ordered reviewed resets. Opening it re-audits the processed prefix rather than
trusting stored accepted states or payout claims. Collecting candidates, pauses,
refunds, completed records and original reset boundaries are rebuilt. Nothing
processes beyond the saved cursor until you click a processing control.

Automatic review recovery uses a separate browser save from simulation recovery.
Changed reviews are saved every 3 seconds when storage is available. Recover review
opens that save manually. Startup never resumes a review automatically. Browser
storage can be unavailable, full, cleared or associated with a different extracted
location; use Save review progress for a portable copy. A failed automatic write
leaves the prior save in place. Clear automatic review save removes the stored copy;
further review changes can create a new one. Closing before a save can lose progress.

Limits: 5,000 source frames / 10 MB sequence; 10,000 total frame/reset operations;
20 MB UTF-8 review file. Restoring rebuilds the saved prefix synchronously, so a
large review can briefly occupy the page. These are file/log bounds, not measured
whole-process RAM limits. A different audit-rules version is refused.

The inspector includes only accepted state changes, with original source-frame
numbers, anchor street and fixed payout-policy scope. It retains at most the last
256 accepted steps for a selected hand and labels omissions. Only the most recent
100 completed records are selectable; all source frames still remain in review
files within the source limit. Record numbers are local to that review. Reset
breaks continuous verification even if the same hand label is reused.

Save review progress is the RESUMABLE format. Export audit, Export completed hands
and Export selected hand review remain READ-ONLY REPORTS. Opening or inspecting
any of these files does not authenticate their source. Modified source evidence is
re-audited under the supported rules, not compared against an authenticated original.
Study drafts/results, entered ranges, image calibration and screenshot pixels are
not part of review recovery. No solver request or client action is started.
See docs/REVIEW-SESSIONS.md for exact format details.

Accounting requires an already reconstructed CLOSED round. Refunds and final
payouts use explicit phase fields, payout arrays and observed final stacks.
The tracker checks uncalled excess, contribution layers, eligibility, exposed
hand strength, split pots and integer odd chips. Adjacent layers with the same
eligible seats are merged before rounding. Odd chips go clockwise from dealer.
This fixed policy may not match every room. No rake/fee deduction is modeled.

Contested pots require a complete river board and explicit cards for ALL eligible
players, including an explicit hero seat. Mucked or missing hands can prevent
verification; no hidden cards are invented. An uncontested fold win needs no
opponent showdown. This accounting uses INTEGER CHIPS, unlike continuous-BB
controlled solver practice.

The refunds array describes THIS accounting transition, not a cumulative display.
A separate refund is credited first; a subsequent payout must not credit it again.
Completed records retain cumulative observed refunds separately from pot awards.
Awards are gross pot distributions, NOT net profit.

seat count/blind level remain unchanged, dealer rotates correctly, balances carry
forward and a full supported preflop posting anchor is supplied. The default new-
hand gap allowance is 60 seconds; normal within-hand gaps remain capped at 2 seconds.
Seat moves, bustouts, blind increases, rebuys and unsupported posts still need an
explicit reviewed reset. Reset breaks continuous-session verification.

Completed records include the initial accepted snapshot, retained action history,
verified pot allocations, final stacks and their anchor street. A river-start
record does not certify the earlier streets. At most 100 completed records and
256 transitions per hand are retained; truncation is marked. Record IDs are local
to this review run. Export before loading another sequence or closing the page.
These exports are READ-ONLY REPORTS, not resumable checkpoints or an authenticated
site hand history. Reopen the original observation sequence to repeat the review.
The interface displays compact summaries; exports contain full retained details.

Refund/showdown/settlement phases are documented in docs/OBSERVATIONS.md. A combined
last action and chip payout cannot be guessed; supply a stable closed-round
observation before the payout. Unknown or contradictory evidence pauses that table.
Every report remains decisionReady=false. No solver or client action is started.

WHAT CONTROLLED PLAY DOES
It trains the configured study, samples a compatible synthetic deal from its
weighted ranges, then uses each acting seat's available EightMax policy row.
The same source engine supplies betting transitions and action menus. It stops
if a policy row is missing instead of inventing a fallback. A blocked hand may
need narrower ranges or more training. Existing rows follow EightMax's own
average-policy normalization; a returned uniform policy is not convergence proof.

Practice is reproducible from its seed and does not change the trained strategy.
It supports chip-EV studies only in this milestone; ICM study analysis remains
available separately. Pot awards use continuous BB inside the betting abstraction,
not integer-chip rounding. Practice state is not a full tournament or a live game.

The ten-table dashboard STILL uses its labeled scripted policy. Controlled
solver-driven play is a separate study mode, not an automatic retrofit of arbitrary
mid-hand states from the dashboard. Neither mode accesses KKPoker.

EXACT-SETTINGS CACHE
A completed portable CPU study may be reused only for the same normalized settings,
source build, update count and time budget. A hit is labeled, with its ORIGINAL
solve time preserved. It is not new training. Partial, native, reviewed-position
and practice results are excluded. The in-memory cache is bounded to 32 entries / about 4 MB of accounted
key/result strings; this is not a total JavaScript heap cap. Closing the page clears it.
